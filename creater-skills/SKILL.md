# 多形态教学内容创作

以独立的 1600×900 React 页面组织课程。Guide 按教学顺序纵向阅读，PPT 逐页播放；两者共享核心知识、页面顺序和主要交互。

**让知识逐渐显现，让操作承担解释，让学习自然发生。** 每页围绕一个学生应能回答的问题，先体验后抽象，让图形与操作解释关系。保持一个主要视觉重点，用少量大区域形成清楚的阅读顺序。

## 模板目录与准备阶段

本模板使用四个主目录：`creater-skills/` 放创作规范、Shared 和工具，`runtime/` 放预览与后端，`environment/` 放依赖和配置，`courses/` 放课程内容。实现位于 `courses/modules/<课程名>/`，公共组件通过 `@shared/react` 导入。

从项目根目录运行 `./environment/install.ps1` 安装、`./runtime/start.ps1` 预览、`./runtime/stop.ps1` 停止、`./creater-skills/check.ps1` 验证。原生前端命令使用 `npm --prefix environment/frontend run <脚本>`；构建输出在 `runtime/data/build/frontend/`。

**首次只收到术库的创作／共创说明时，先准备，等待具体创作指令。** 下载或沿用本地项目、读取所需规范、保存给定课程信息及根目录 `api_token` 后，简短询问用户想怎样设计或修改。不因为说明里有标题、简介或阶段备注就生成大纲、教学页面、正式素材，或执行构建、上传和提交。已有课程、密钥、身份和上传清单保持原样；用户已经明确给出具体制作或修改任务时，直接按该任务及已有授权推进。

## 先判断当前任务

先读用户指定的模块、相关页面和已有大纲；若模块有 `docs/authoring-decisions.md`，只核对相关页面的既定决定。沿用本次对话中已确认的方向与授权；不要把所有任务都从新建课程流程重新开始。

| 当前任务 | 执行方式 |
|---|---|
| 仅收到术库创作／共创说明 | 只完成本地准备，等待具体指令，不开始制作或上传 |
| 新建课程 | 理解受众与目标 → 确认大纲 → 逐页设计、实现与验收 |
| 设计下一页、预览或重新设计 | 沿用已确认大纲，给出文字说明与实际生成的设计图；确认方向后实现 |
| 修改已有页面 | 只处理指定范围；若要改变视觉方向，先预览确认；文字、数值、资源引用等局部修改直接落实 |
| 修复代码、交互或布局缺陷 | 定位 → 修复 → 针对性验证；不重新要求课程大纲或生成设计图 |
| 转换 PPT、截图或既有课件 | 识别忠实转换、借鉴或重新设计的意图，再按转换范围推进 |
| 用户要求上传或提交共创 | 按上传／共创 Skill 处理，区分术库私有工作区与个人 Fork |
| 仅讨论、评审或修改 skill | 输出所请求的判断或修改，不触发课程制作流程 |

“修改”若实际提出全新构图或交互方案，应走设计流程；修复溢出、错位或恢复已确认效果不算重新设计。

## 创作与确认

1. **理解目标。** 明确讲什么、给谁学习、学生已有基础、重点和期望效果。新建课程时选读 `/shared/ui-kit` 对应组件与当前项目已有课程的相关实现，了解质量基线；没有已有课程时从 UI Kit 开始，不要求下载参考仓库的示例课程，也不照搬其结构或构图。
2. **先确认大纲。** 新课程先讨论并迭代模块根目录的 `outlines.json`；大纲未确认前，不生成第一页设计图、不实现页面。已有已确认大纲直接沿用；单页修改不要求重建大纲。用户明确要求跳过时遵循当前授权。
3. **提供真实预览。** 设计新页、下一页或调整设计方案时，默认同时提供简短文字和实际生成、展示的设计示意图（如 ImageGen）。文字说明教学目标、视觉主角与核心交互；示意图按 1600×900 构图，保留现有 UI 体系。生成图只代表设计，不代表已实现效果或真实计算结果。
4. **确认后实现。** 默认逐页确认设计，再创建或修改该页 React、CSS 和正式素材；确认前允许生成讨论用的设计图。实现后展示实际渲染结果，用户确认满意后继续下一页。
5. **承接已有授权。** 用户已认可示意图或明确不需要生图时不重复生成；明确要求直接实现、跳过预览或连续制作时，在已确认方向和授权范围内推进，不逐页重复索要许可。每页仍需独立验证。

图像生成能力不可用或失败时，说明实际情况，不把文字或提示词称为已完成的视觉预览。尚未获得实现授权时保留设计讨论状态；已有直接实现授权时按授权推进。

## 工程边界

- 教学页固定 **1600×900**，空间不足由外层整体等比例缩放，禁止响应式重排。内容必须完整容纳，不以裁切或横向滚动掩盖溢出。
- 写代码前检查 Shared 的对应能力。标准页用 `ContentBlock` 默认标题区，文字必须使用 `Typography`，数学表达用 `MathFormulaBlock`，基础视觉沿用 Shared Theme；具体使用边界见工程说明。
- 未经用户明确要求，不修改 `creater-skills/shared/`。
- 静态资源放 **`courses/assets/<moduleIdentity.id>/`**，通过 `moduleAssetUrl` 引用，SceneDeck `assetId` 使用同一 UUID。本模板仍使用 UUID 与 Ed25519 签名身份；新模块按身份指南签发，已有课程的身份、密钥及 URL 不因普通修改而重建。
- 除非用户明确要求，不查看 Git 历史。

用户明确提出的课程或页面例外只适用于所指范围，不扩展为其他页面或共创者的默认要求。遵守仓库 `AGENTS.md`，发现冲突时结合用户当前指令处理。

## 完成条件

交付与请求相匹配的结果。页面实现需核对内容、实际截图、画布边界及相关交互，发现问题后修复并复查受影响状态。局部修复只验证受影响范围；纯文档修改检查结构、引用和规则一致性，无需启动课程服务。

说明改了什么、验证了什么、还有哪些实际限制。设计图与真实页面分别标明；未完成的验证如实说明。不额外生成没有用途的 Brief、Visual Plan、评分表或流程报告。

## 术库上传与共创

- 用户要求上传阶段版本时读取 [上传课程 Skill](upload/SKILL.md) 和 [UPLOAD.md](../UPLOAD.md)：本地构建可用预览，打包 `courses/`，从根目录 `api_token` 读取凭证。保持服务器给定的 `courseKey`，凭证不随课程包上传。
- 已有课程的个人 GitHub Fork 共创按 [共创编辑 Skill](collaboration/SKILL.md) 修改、预览并提交 PR；术库私有工作区按说明使用上传通路。首次准备不执行上传或 PR 提交。
- 课程库规范元数据位于 `courses/modules/`，按 [Shuku 格式](guides/shuku-format.md) 维护；平台上传清单位于 `courses/shuku.json`，两者用途不同，不能互相覆盖。实际仓库来源未知时保留待配置状态，不编造地址。
